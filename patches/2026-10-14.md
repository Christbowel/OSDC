## GHSA-m6wq-39m7-9xpp · Metalama.Framework

2026-10-14 · C# · **MODERATE** 8.2 · Pattern: `PRIVILEGE_ESCALATION→ROLE`

### Root cause

The application used `Path.GetTempPath()` to determine a temporary directory for storing and loading assemblies. On Unix-like systems, `Path.GetTempPath()` often resolves to `/tmp`, which is a world-writable directory. This allowed a local attacker to plant malicious DLLs in the expected temporary directory, which the application would then load and execute.

### Impact

A local attacker could achieve arbitrary code execution with the privileges of the user running the Metalama application by placing a malicious DLL in the shared temporary directory.

The `GetTempFileName` method was also updated to accept a directory parameter, allowing callers to specify a secure temporary location.

## GHSA-7pxr-59rr-hqj2 · Microsoft.OpenApi.Readers

2026-10-14 · C# · **HIGH** 7.5 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The Microsoft.OpenApi.YamlReader library was vulnerable to excessive resource consumption when parsing YAML documents containing deeply nested structures or extensive use of YAML aliases (anchors and references). This could lead to a 'billion laughs' attack where a small YAML input expands exponentially in memory and processing, exhausting system resources.

### Impact

An attacker could provide a specially crafted YAML document to an application using this library, causing the application to consume excessive CPU and memory, leading to a denial of service for legitimate users.

## GHSA-856c-92hv-3vxx · apprise

2026-10-14 · Python · **LOW** 3.1 · Pattern: `SSRF→INTERNAL_ACCESS`

### Root cause

The Apprise library, when configured to use authentication headers for HTTP requests, would automatically forward these headers to new locations during cross-origin HTTP redirects. This behavior is the default for the underlying 'requests' library but was not explicitly controlled or prevented by Apprise, leading to credentials being sent to unintended third-party domains.

### Impact

An attacker could potentially redirect a legitimate request to a malicious server, causing the authentication headers (e.g., API keys, tokens) to be leaked to the attacker's controlled domain. This could lead to unauthorized access to the user's accounts or services.

## GHSA-xpf3-p7gm-7756 · bbot

2026-10-14 · Python · **LOW** 3.1 · Pattern: `PATH_TRAVERSAL→FILE_WRITE`

### Root cause

The original implementation of the unarchive module used various Python libraries for archive extraction. These libraries, when used without proper sanitization or symlink protection, could be tricked into following symbolic links present within a malicious archive. This allowed an attacker to write files outside the intended extraction directory.

### Impact

An attacker could plant symbolic links during archive extraction, leading to arbitrary file write outside the designated directory. This could result in overwriting critical system files or planting malicious executables.
