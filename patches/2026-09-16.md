## GHSA-cv3r-c5h8-f4g5 · @zereight/mcp-gitlab

2026-09-16 · JavaScript · **CRITICAL** 9.8 · Pattern: `MISSING_AUTH→ENDPOINT`

### Root cause

The application exposed an SSE (Server-Sent Events) server endpoint without proper authentication by default. This allowed an unauthenticated attacker to connect to the SSE server and potentially interact with internal functionalities, including the `upload_markdown` feature, which could be leveraged to read arbitrary files.

### Impact

An attacker could read arbitrary files from the server, including sensitive configuration files or Personal Access Tokens (PATs), leading to full account takeover and access to other internal resources.

## GHSA-r2pf-9cw4-5j65 · node-opcua

2026-09-16 · JavaScript · **HIGH** 7.0 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The vulnerability existed because the TCP socket was not properly destroyed when an error occurred during the read operation. Instead of destroying the socket, it was only 'ended', which left the socket in a FIN-WAIT-2 state, preventing its resources from being fully released.

### Impact

An attacker could trigger a large number of these errors, leading to an accumulation of sockets in the FIN-WAIT-2 state. This would eventually exhaust the available TCP socket resources on the server, causing a Denial of Service.

### Key diff

```
-            if (this._socket) {
-                this._socket.end();
+            if (this._socket) {
+                const s = this._socket;
+                this._socket = null;
+                s.destroy();
            }
```

### Fix summary

The patch addresses the vulnerability by ensuring that when an error occurs or no data is received, the TCP socket is explicitly destroyed using `s.destroy()` instead of just `this._socket.end()`. Additionally, the `_socket` reference is nulled out to prevent further use of the defunct socket.
