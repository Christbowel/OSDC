## GHSA-2qvg-qr73-mqxp · wktk/conflibot

2026-08-17 · YAML · **CRITICAL** 9.1 · Pattern: `UNSANITIZED_INPUT→COMMAND`

### Root cause

The application was executing Git commands by directly concatenating user-controlled input (specifically, pull request branch names) into a shell command string. This allowed an attacker to inject arbitrary shell commands by crafting a malicious branch name.

### Impact

An attacker could execute arbitrary commands on the runner machine where the GitHub Action was being executed, leading to full compromise of the environment and potential access to sensitive data or resources.


### Fix summary

The patch replaces the use of `child_process.exec` with `child_process.execFile` and `child_process.spawn`. This change ensures that Git commands are executed directly with an array of arguments, preventing shell interpretation of user-controlled strings and eliminating the command injection vulnerability.

## GHSA-m44r-7c5h-m6mj · @medplum/core

2026-08-17 · JavaScript · **HIGH** 7.1 · Pattern: `OPEN_REDIRECT→PHISHING`

### Root cause

The application improperly validated redirect URIs in the external authentication callback. It allowed partial matches for redirect URIs, which could be exploited by an attacker to redirect authorization codes to a malicious domain if the legitimate redirect URI was a prefix of the attacker's controlled URI.

### Impact

An attacker could intercept authorization codes, potentially leading to account takeover or unauthorized access to user data by exchanging the stolen code for an access token.

### Key diff

```

-    const redirectUri = getClientRedirectUri(client, body.redirectUri, true);
-    if (!redirectUri) {
-      sendOutcome(res, badRequest('Invalid redirect URI'));
-      return;
-    }
-    const exactRedirectUri = getClientRedirectUri(client, redirectUri);
-    if (!exactRedirectUri) {
+    let redirectUri = getClientRedirectUri(client, body.redirectUri);
+
+    if (!redirectUri && (await isDangerousRedirectUriPartialMatchAllowed(client))) {
+      redirectUri = getClientRedirectUri(client, body.redirectUri, true);
+    }
+
+    if (!redirectUri) {
+      sendOutcome(res, badRequest('Invalid redirect URI'));
+      return;
+    }
```

### Fix summary

The patch tightens the redirect URI validation logic. Partial matching is now only allowed if explicitly enabled via a 'allow-dangerous-redirect' project setting. Additionally, the partial matching logic itself was improved to ensure that only the path, not the entire origin, can be partially matched, preventing redirection to arbitrary origins.
