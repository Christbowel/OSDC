## GHSA-jrw6-7x4q-w25j · senaite.core

2026-08-26 · Python · **CRITICAL** 9.8 · Pattern: `UNSANITIZED_INPUT→COMMAND`

### Root cause

The application used Python's `eval()` function to parse stringified record values from user-controlled input. The `eval()` function executes arbitrary Python code, making it highly dangerous when used with untrusted input.

### Impact

An attacker could achieve arbitrary code execution on the server, leading to full system compromise, data exfiltration, or denial of service.

## GHSA-79gf-7frw-68m9 · github.com/kyverno/kyverno

2026-08-26 · Go · **CRITICAL** 9.6 · Pattern: `PRIVILEGE_ESCALATION→ROLE`

### Root cause

The Kyverno background controller's `generator.apply()` function did not properly validate the `namespace` argument when generating resources. This allowed a namespaced policy to generate cluster-scoped resources, such as RoleBindings, in any namespace, including sensitive ones like `kube-system`, effectively bypassing intended scope restrictions.

### Impact

An attacker with permissions to create namespaced Kyverno policies could escalate privileges by creating cluster-scoped resources (e.g., RoleBindings) in arbitrary namespaces, potentially granting themselves or other malicious actors administrative access to the Kubernetes cluster.

## GHSA-m452-q8c9-rg2f · org.asynchttpclient:async-http-client

2026-08-26 · Java · **MODERATE** 4.0 · Pattern: `UNCLASSIFIED`

### Root cause

The `ThreadSafeCookieStore` in AsyncHttpClient did not properly validate the `Domain` attribute of incoming cookies against the request host. This allowed a malicious server to set a cookie for an unrelated domain if the request host was a subdomain of the cookie's domain, or if the cookie's domain was simply a substring of the request host, violating RFC6265.

### Impact

An attacker could potentially set cookies for a victim's browser for a domain they do not control, leading to session fixation, authentication bypass, or other malicious activities if the victim later visits the targeted domain.

### Key diff

```
--- a/client/src/main/java/org/asynchttpclient/cookie/ThreadSafeCookieStore.java
+++ b/client/src/main/java/org/asynchttpclient/cookie/ThreadSafeCookieStore.java
@@ -164,6 +169,14 @@ private void add(String requestDomain, String requestPath, Cookie cookie) {
     AbstractMap.SimpleEntry<String, Boolean> pair = cookieDomain(cookie.domain(), requestDomain);
     String keyDomain = pair.getKey();
     boolean hostOnly = pair.getValue();
+
+    // rfc6265#section-5.3 step 6: ignore a cookie whose Domain attribute is not
+    // domain-matched by the request host, otherwise a host can plant cookies for
+    // unrelated domains (cookie tossing).
+    if (!hostOnly && !domainsMatch(keyDomain, requestDomain)) {
+      return;
+    }
+
     String keyPath = cookiePath(cookie.path(), requestPath);
     CookieKey key = new CookieKey(cookie.name().toLowerCase(), keyPath);
```

### Fix summary

The patch introduces a `domainsMatch` helper method and adds a check in the `add` method to ensure that a cookie's `Domain` attribute is strictly domain-matched by the request host, as per RFC6265 section 5.3 step 6. If the domains do not properly match and the cookie is not host-only, the cookie is ignored.
