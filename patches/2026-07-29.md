## GHSA-38c3-wv3c-v3xj · swagger-typescript-api

2026-07-29 · JavaScript · **HIGH** 8.3 · Pattern: `SSRF→INTERNAL_ACCESS`

### Root cause

The `swagger-typescript-api` package was vulnerable to Server-Side Request Forgery (SSRF) because it would fetch external OpenAPI schemas and their `$ref` references without proper validation of the target URLs. An attacker could craft a malicious OpenAPI schema with `servers[0].url` or `$ref` fields pointing to internal network resources or sensitive services.

### Impact

An attacker could force the application to make requests to arbitrary internal network resources, potentially leading to information disclosure, port scanning, or interaction with internal services not intended to be exposed externally.

+      );

### Fix summary

The patch introduces a new `remote-schema-fetch.ts` utility that implements strict validation for remote schema URLs. ## GHSA-5f94-x226-ccpm · swagger-typescript-api

2026-07-29 · JavaScript · **HIGH** 8.3 · Pattern: `SSRF→INTERNAL_ACCESS`

### Root cause

The `swagger-typescript-api` package could fetch external OpenAPI/Swagger schemas and their referenced external schemas without sufficient validation of the target URLs. This allowed an attacker to specify a URL that would resolve to an internal network resource or a local file, bypassing intended network restrictions.

### Impact

An attacker could perform Server-Side Request Forgery (SSRF) to access internal network resources, potentially leading to information disclosure, port scanning, or interaction with internal services that are not exposed to the public internet.

The `fetch` calls are updated to use this new validation logic.

## GHSA-px9f-whj3-246m · req

2026-07-29 · Erlang · **MODERATE** 0.0 · Pattern: `UNSANITIZED_INPUT→HEADER`

### Root cause

The application was vulnerable to header injection because it did not properly escape user-controlled input (filename, content_type, and name) when constructing multipart form-data headers. This allowed attackers to inject newlines and arbitrary header fields.

### Impact

An attacker could inject arbitrary headers into the multipart form-data, potentially leading to various issues depending on how the receiving server processes these headers, such as cache poisoning or unexpected application behavior.

This prevents the injection of newlines and other special characters into the multipart headers.
