## GHSA-rr49-f9g6-c9r5 · plone.app.portlets

2026-09-23 · Python · **CRITICAL** 9.9 · Pattern: `UNSANITIZED_INPUT→TEMPLATE`

### Root cause

The application allowed user-controlled input (template and macro names) to be directly used in a TALES (TAL Expression Syntax) path expression without sufficient validation. This enabled an attacker to inject TALES metacharacters, transforming a simple path traversal into an arbitrary TALES expression, which could then execute Python code.

### Impact

An attacker could achieve arbitrary remote code execution on the server, leading to full compromise of the application and potentially the underlying system.

## GHSA-x5c9-v98j-722r · 9router

The application incorrectly determined if a request was local by only checking the TCP socket's remote address. ## GHSA-r2xf-8xr9-62gw · org.jline:jline-builtins

2026-09-23 · Java · **HIGH** 7.5 · Pattern: `UNSANITIZED_INPUT→REGEX`

### Root cause

The vulnerability stemmed from the JLine library's built-in 'grep' command, which automatically wrapped user-provided search patterns with '.*'. This behavior, combined with the use of a backtracking regex engine, allowed for the creation of 'catastrophic backtracking' regular expressions. When a specially crafted, complex regex pattern was applied to a non-matching input, the regex engine would consume excessive CPU resources, leading to a denial of service.

### Impact

An attacker could craft a malicious regular expression that, when processed by the JLine 'grep' command, would cause the application to become unresponsive or crash due to excessive CPU consumption, effectively denying service to legitimate users.

## GHSA-cmhj-wh2f-9cgx · 9router

An attacker could exploit DNS rebinding by having the DNS server initially return a public IP, and then return a private IP on a subsequent lookup (or during the connection phase if the DNS TTL expired), allowing the application to connect to internal services.

### Impact

An attacker could bypass the SSRF protection and make the server fetch resources from internal network services, potentially leading to information disclosure, unauthorized access, or further attacks on the internal infrastructure.

## GHSA-6cp7-3m3c-5x5c · zapros

2026-09-23 · Python · **HIGH** 0.0 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The streaming decoders (GZip, Deflate, Brotli, ZStandard) in `zapros` did not respect the requested chunk size when decompressing data. This allowed a malicious actor to send a single, highly compressed response chunk that, when decompressed, would allocate an unbounded amount of memory, leading to a 'decompression bomb' scenario.

### Impact

An attacker could cause the server or client processing the compressed data to consume excessive memory, leading to a denial of service (DoS) by crashing the application or exhausting system resources.
