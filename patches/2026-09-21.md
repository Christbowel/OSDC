## GHSA-phg3-3g28-wq9v · hatchet

2026-09-21 · Go · **HIGH** 7.1 · Pattern: `CSRF→STATE_CHANGE`

### Root cause

The application's OAuth state validation mechanism was vulnerable to an empty-state collision. If an attacker could make a victim initiate an OAuth flow without a 'state' parameter, or with an empty 'state' parameter, the application would treat this as a valid state, allowing the attacker to link their account to the victim's session.

### Impact

An attacker could perform an unauthenticated OAuth state CSRF, leading to a login CSRF. This would allow the attacker to link their own OAuth account to a victim's session, effectively taking over the victim's account or forcing them to log in as the attacker.

### Fix summary

The patch adds an explicit check to ensure the 'state' parameter is not empty. It also uses `subtle.ConstantTimeCompare` for state comparison to prevent timing side-channel attacks and completely removes the state keys from the session after validation instead of just clearing their values, ensuring single-use.
