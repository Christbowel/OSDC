## GHSA-jm85-8cpp-9cjc · adminneo-org/adminneo

2026-10-30 · PHP · **HIGH** 7.5 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The application stored version information in a serialized file without proper validation of the input. An attacker could send a crafted POST request to the 'script=version' endpoint with an array as the 'version' parameter, which would then be serialized and stored in the 'adminneo.version' file. Subsequent attempts to unserialize this malformed data would fail, leading to a persistent denial of service.

### Impact

An attacker could cause a persistent denial of service, preventing legitimate users from accessing the AdminNeo interface due to the application's inability to process the corrupted version file.

## GHSA-jpxq-7h8p-2q76 · joserfc

2026-10-30 · Python · **HIGH** 7.5 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The application processed an unbounded number of recipients in a JWE General JSON Serialization. Each recipient required a private-key decryption operation, which is computationally expensive. An attacker could craft a JWE with a large number of recipients, leading to excessive CPU usage and resource exhaustion.

### Impact

An attacker could cause a denial of service by sending a maliciously crafted JWE, preventing legitimate users from accessing the service and potentially crashing the server due to CPU exhaustion.

## GHSA-qm8w-vx34-5j9j · @nx/gradle

2026-10-30 · JavaScript · **HIGH** 0.0 · Pattern: `UNSANITIZED_INPUT→COMMAND`

### Root cause

The vulnerability stemmed from the way command-line arguments, particularly those originating from `nx.json` plugin options, were handled when spawning child processes on Windows. Specifically, special shell characters like `&` in arguments were not properly quoted or escaped, leading to their interpretation as command separators by the Windows command shell (`cmd.exe`) when `shell: true` was implicitly or explicitly used.

### Impact

An attacker could inject arbitrary OS commands by crafting malicious input within `nx.json` plugin options. These commands would then be executed on the victim's machine, potentially leading to remote code execution, data exfiltration, or system compromise.

### Fix summary

The patch introduces `safeSpawn` and `safeExecFileSync` utilities that carefully handle command execution, especially on Windows. It implements robust quoting mechanisms for binary paths and arguments containing special shell characters (like `&` and spaces) when a shell is used. It also explicitly refuses arguments or binary paths containing line breaks or double quotes on Windows to prevent command injection, while ensuring that arguments are passed literally without a shell on non-Windows platforms.
