## GHSA-w5f2-9q9c-ff4h · lmcache

2026-10-16 · Python · **CRITICAL** 9.8 · Pattern: `DESERIALIZATION→RCE`

### Root cause

The `lmcache` library, when operating in multiprocess mode, used Python's `pickle` module for inter-process communication (IPC) of `DeviceIPCWrapper` objects. The `pickle` module is known to be insecure against maliciously crafted data, as it can execute arbitrary code during deserialization. An attacker could send a specially crafted pickled object to a process expecting a `DeviceIPCWrapper`, leading to arbitrary code execution.

### Impact

An attacker could achieve remote code execution on the system running the `lmcache` application, potentially gaining full control over the affected process and its resources.

### Key diff

### Fix summary

The patch replaces Python's `pickle`-based serialization for IPC with `msgspec`, a more secure and explicit serialization library. It introduces new `to_wire` and `from_wire` methods for `CudaIPCWrapper`, `RawCudaIPCWrapper`, and `VmmCudaIPCWrapper` classes, which serialize and deserialize only the necessary data using `msgspec.Struct` definitions, preventing arbitrary code execution during deserialization.

## GHSA-h4mw-j7qp-8mwm · claude-agent-sdk

2026-10-16 · Python · **CRITICAL** 0.0 · Pattern: `UNSANITIZED_INPUT→COMMAND`

### Root cause

The vulnerability existed because the `_build_command` function constructed subprocess commands by appending user-controlled options directly as separate arguments (tokens) to the command list. Specifically, for options like `--resume` and `--session-id`, if a user-supplied value started with a dash, it would be parsed as a new CLI flag rather than as the value for the intended option, allowing for arbitrary command-line argument injection.

### Impact

An attacker could inject arbitrary command-line arguments into the `claude-cli` subprocess, potentially leading to arbitrary command execution on the system where the SDK is used.

### Key diff

```
-            cmd.extend(["--resume", self._options.resume])
+            cmd.append(f"--resume={self._options.resume}")
 
         if self._options.session_id:
-            cmd.extend(["--session-id", self._options.session_id])
+            cmd.append(f"--session-id={self._options.session_id}")
```

### Fix summary

The patch modifies how the `--resume` and `--session-id` options are passed to the subprocess. Instead of using `cmd.extend(["--flag", value])`, it now uses `cmd.append(f"--flag={value}")`. This change ensures that the value is always bound to its respective flag, preventing a dash-leading value from being interpreted as a new, separate CLI flag.
