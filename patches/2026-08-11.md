## GHSA-87fv-vqqr-m4jr · github.com/seaweedfs/seaweedfs

2026-08-11 · Go · **CRITICAL** 9.3 · Pattern: `SSRF→CLOUD_METADATA`

### Root cause

The SeaweedFS VolumeServer's FetchAndWriteNeedle function allowed unauthenticated requests to fetch data from a remote S3 endpoint. Crucially, the application did not adequately validate the provided S3 endpoint URL, allowing an attacker to specify arbitrary internal or external URLs. This lack of validation, combined with the ability to read back the response, created an SSRF vulnerability.

### Impact

An unauthenticated attacker could force the SeaweedFS server to make requests to arbitrary internal network resources, including cloud instance metadata services (IMDS), and read the responses. This could lead to the disclosure of sensitive information, such as cloud credentials or internal network topology, and potentially facilitate further attacks.

### Fix summary

The patch introduces robust validation for remote S3 endpoints. It now explicitly blocks well-known IMDS hostnames, loopback, link-local, unspecified, private (RFC 1918), and CGNAT IP addresses. Furthermore, it implements a `guardedDialer` that re-validates IP addresses immediately before dialing, mitigating DNS rebinding attacks by preventing the target IP from changing to a blocked address after initial validation.
