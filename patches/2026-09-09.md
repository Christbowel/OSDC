## GHSA-7rhf-42qf-vrvc · gix-sec

2026-09-09 · RUST · **MODERATE** 6.8 · Pattern: `PRIVILEGE_ESCALATION→ROLE`

### Root cause

The `gix-sec` library's `is_path_owned_by_current_user` function on Windows incorrectly determined ownership for directories owned by the Administrators group. It failed to properly check if an elevated administrator, running with a split token, was a member of the Administrators group by only checking the unelevated token. This allowed an attacker to create a malicious `.git` directory in a location owned by the Administrators group, which would then be considered 'safe' by the library.

### Impact

An attacker could trick an elevated administrator into running Git commands in a directory they control, potentially leading to arbitrary code execution. This bypasses the `safe.directory` protections designed to prevent untrusted repository execution.

```
-            if CheckTokenMembership(std::ptr::null_mut(), token_owner, &mut is_member) == 0 {
-                error!("Couldn't check if user is an administrator");
+            if CheckTokenMembership(linked_token.as_raw_handle() as _, folder_owner, &mut is_member) == 0 {
+                error!("Couldn't check if elevated user is an administrator");
```

### Fix summary

The patch introduces a new `token_information` helper function to reliably retrieve token information. It modifies the `is_path_owned_by_current_user` function to correctly handle elevated administrators on Windows by checking the linked (elevated) token for group membership when the current token is a limited token.
