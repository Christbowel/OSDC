## GHSA-x2rj-828p-hx9m · xinference

2026-08-21 · Python · **CRITICAL** 10.0 · Pattern: `UNSANITIZED_INPUT→COMMAND`

### Root cause

The application used the unsafe `eval()` function to parse tool-call arguments from untrusted model outputs. An attacker could craft a malicious string that, when evaluated by `eval()`, would execute arbitrary Python code on the server.

### Impact

An attacker could achieve full remote code execution on the server hosting the Xinference application, leading to complete system compromise.

### Key diff

```
--- a/xinference/model/llm/utils.py
+++ b/xinference/model/llm/utils.py
-            data = eval(text, {}, {})
+            data = json.loads(text)
+        except (json.JSONDecodeError, TypeError):
+            try:
+                data = ast.literal_eval(text)
```

### Fix summary

The patch replaces the unsafe `eval()` calls with a safer parsing mechanism. It first attempts to parse the input as JSON and, if that fails, falls back to `ast.literal_eval()`. `ast.literal_eval()` is a safe alternative to `eval()` for evaluating strings containing Python literal structures, preventing arbitrary code execution.

## GHSA-hrwp-4hh9-c8r8 · phalcon/cphalcon

2026-08-21 · PHP · **CRITICAL** 0.0 · Pattern: `UNSANITIZED_INPUT→TEMPLATE`

### Root cause

The Volt compiler's 'join' filter directly concatenated the string value of the second argument (the glue) into the generated PHP code without proper sanitization or expression evaluation. This allowed an attacker to inject arbitrary PHP code into the compiled template.

### Impact

An attacker could achieve Remote Code Execution (RCE) by injecting malicious PHP code into the 'join' filter's glue argument, which would then be executed when the compiled template is rendered.

### Key diff

```
-				return "join('" . funcArguments[1]["expr"]["value"]
-					. "', " . funcArguments[0]["expr"]["value"] . ")";
+				return "join(" . this->expression(funcArguments[1]["expr"])
+					. ", " . this->expression(funcArguments[0]["expr"]) . ")";
```

### Fix summary

The patch modifies the 'join' filter's compilation logic to use the `this->expression()` method for both arguments. This ensures that the arguments are properly evaluated as expressions, preventing direct string concatenation and thus PHP code injection.
