## GHSA-x585-4vv8-2mh2 · rucio

2026-11-13 · Python · **CRITICAL** 9.8 · Pattern: `MISSING_VERIFICATION→SIGNATURE`

### Root cause

The system incorrectly allowed SSH challenge tokens, which are intended as nonces for signing, to be used directly as authentication tokens. This design flaw meant that a token meant for a cryptographic challenge could be re-purposed to authenticate a request without proper signature verification.

### Impact

An unauthenticated attacker could impersonate an administrator by presenting a valid SSH challenge token, gaining full administrative control over the Rucio instance.

### Key diff

```
# SSH challenge tokens share this table but are nonces to be signed, not
    # credentials, so they must never authenticate a request on their own.
    if token.startswith('challenge-'):
        raise CannotAuthenticate("Challenge tokens cannot be used for authentication.")
```

### Fix summary

The patch introduces a check at the beginning of the token validation process. If a token starts with 'challenge-', it is immediately rejected with a 'CannotAuthenticate' error, preventing challenge tokens from being used as direct authentication credentials.

## GHSA-mmhr-3c5m-f64f · soupsieve

2026-11-13 · Python · **HIGH** 7.5 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The vulnerability stemmed from an inefficient algorithm used for the descendant combinator in CSS matching. When processing deeply nested HTML structures with multiple descendant combinators, the algorithm would repeatedly traverse the ancestor chain for each combinator, leading to a polynomial time complexity proportional to the depth of the document and the number of combinators. This lack of caching for ancestor checks caused redundant computations.

### Impact

An attacker could craft a specially designed HTML document and CSS selector that, when processed by Soup Sieve, would consume excessive CPU resources and time, leading to a denial of service for applications using the library.

### Key diff

```
--- a/soupsieve/css_match.py
+++ b/soupsieve/css_match.py
@@ -998,9 +1025,12 @@ def match_past_relations(self, el: bs4.Tag, relation: ct.SelectorList) -> MatchG
             return found
 
         if relation[0].rel_type == REL_PARENT:
-            parent: bs4.Tag | None = el
-            while not found and parent and (parent := self.get_parent(parent)):
-                found = parent is not None and (yield parent, relation)
+            if self.enable_cache:
+                found = yield from self.match_ancestor(el, relation)
+            else:
+                parent: bs4.Tag | None = el
+                while not found and parent and (parent := self.get_parent(parent)):
+                    found = parent is not None and (yield parent, relation)
```

### Fix summary

The patch introduces an ancestor cache (`anc_cache`) to store the results of ancestor checks. A new `match_ancestor` method utilizes this cache to avoid redundant computations when traversing the parent chain for descendant combinators. This significantly optimizes the performance for deeply nested structures, reducing the complexity from polynomial to linear.
