## GHSA-mqwm-5m85-gmcv · org.gradle:gradle-core

2026-11-23 · Java · **HIGH** 0.0 · Pattern: `INSECURE_DEFAULT→CONFIG`

### Root cause

The Gradle dependency resolution mechanism did not consider 'UnknownHostException' as a critical failure. This meant that if a configured repository became unreachable due to a DNS resolution failure, Gradle would silently ignore it and proceed to try other repositories, potentially including insecure or malicious ones.

### Impact

An attacker could potentially poison DNS or control a network path to make legitimate repositories unreachable, forcing Gradle to resolve dependencies from a malicious repository. This could lead to the injection of malicious artifacts into the build process.

### Fix summary

The patch modifies the `ResolveExceptionAnalyzer` to explicitly check for `UnknownHostException` as a critical failure. By doing so, Gradle will now fail the build immediately if a repository cannot be resolved due to an unknown host, preventing it from falling back to potentially untrusted repositories.

## GHSA-w78c-w6vf-rw82 · org.gradle:gradle-core

2026-11-23 · Java · **HIGH** 0.0 · Pattern: `INSECURE_DEFAULT→CONFIG`

### Root cause

The previous implementation in Gradle's dependency resolution process did not correctly handle and propagate repository failures. Specifically, if a repository was explicitly disabled or encountered a critical failure, this state was not consistently recognized and acted upon across the entire resolution chain. This could lead to Gradle attempting to resolve dependencies from a repository that should have been ignored or marked as failed.

### Impact

An attacker could potentially host malicious artifacts in a repository that Gradle should have disabled or ignored due to a previous failure. If a build then attempts to resolve a dependency, it might inadvertently fetch the malicious artifact from the compromised or disabled repository, leading to code execution or other forms of compromise within the build environment.

### Fix summary

The patch introduces a `RepositoryFailureCollector` to centralize the collection and tracking of repository failures, including marking fatal errors. It also adds an `isRepositoryDisabled()` method to `ModuleComponentRepository` and its wrappers, ensuring that the disabled status of a repository is consistently checked and respected during dependency resolution. This prevents Gradle from attempting to resolve dependencies from repositories that are explicitly disabled or have encountered critical failures.
