## GHSA-28f5-38xr-jh2w · io.appium:java-client

2026-07-28 · Java · **HIGH** 8.2 · Pattern: `SSRF→INTERNAL_ACCESS`

### Root cause

The AppiumCommandExecutor in java-client allowed an unvalidated URL redirect via the `directConnect` feature. An attacker could specify a malicious URL that, when resolved, pointed to internal network resources, loopback addresses, or cloud metadata services, leading to Server-Side Request Forgery (SSRF).

### Impact

An attacker could force the Appium server to make requests to arbitrary internal network resources, potentially leading to information disclosure (e.g., cloud metadata, internal service banners) or interaction with internal services, thereby pivoting within the network.

### Key diff

```
--- a/src/main/java/io/appium/java_client/remote/AppiumCommandExecutor.java
+++ b/src/main/java/io/appium/java_client/remote/AppiumCommandExecutor.java
@@ -155,5 +156,12 @@ protected HttpClient getClient() {
      * @param serverUrl A url to override.
+     * @param serverUrl URL to use for subsequent HTTP requests. Before switching clients, the host is
```

### Fix summary

A new utility class, `DirectConnectUrlSafety`, was introduced to validate URLs used for server overrides. This class checks if the resolved IP address of the provided URL is a loopback, link-local, unspecified, or multicast address, and throws an exception if it is, preventing connections to such disallowed targets.

## GHSA-w6p7-2fxx-4f44 · github.com/pocket-id/pocket-id/backend

2026-07-28 · Go · **HIGH** 0.0 · Pattern: `MISSING_AUTHZ→RESOURCE`

### Root cause

The OIDC refresh token flow did not properly re-validate user authorization status, account disablement, or group restrictions. Once a refresh token was issued, it could be used indefinitely to obtain new access tokens, even if the user's account was disabled, their authorization for the client was revoked, or their group membership no longer allowed access to the client.

### Impact

An attacker could maintain access to a client application using a refresh token even after the associated user account was disabled, the client's authorization was revoked, or the user's group permissions changed, leading to unauthorized access to resources.
