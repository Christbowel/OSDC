## GHSA-gmxc-r82q-347r · libreoffice-convert

2026-08-27 · JavaScript · **MODERATE** 6.5 · Pattern: `PATH_TRAVERSAL→FILE_WRITE`

### Root cause

The application used a user-supplied filename directly without sanitization when creating temporary files. This allowed an attacker to include directory traversal sequences (e.g., `../`) in the filename.

### Impact

An attacker could write arbitrary files to arbitrary locations on the file system where the application had write permissions, potentially leading to remote code execution or denial of service.

### Key diff

```
-	const fileName = (options || {}).fileName || 'source';
+	const fileName = path.basename((options || {}).fileName || 'source');
```

### Fix summary

The patch addresses the vulnerability by using `path.basename()` on the user-supplied `fileName` option. This ensures that only the base name of the file is used, effectively stripping any directory traversal sequences and preventing files from being written outside the intended temporary directory.

## GHSA-6hx8-3wjj-gr8g · webob

2026-08-27 · Python · **MODERATE** 6.1 · Pattern: `OPEN_REDIRECT→PHISHING`

### Root cause

The `webob` library used `urllib.parse.urljoin` for normalizing `Location` headers. This standard library function, particularly in Python 3.10+, performs whitespace removal (ASCII tab, CR, LF) and strips leading/trailing C0 control and space characters before parsing URLs. This behavior could transform an otherwise relative or harmless URL, such as one starting with ` //evil.example` (with leading spaces), into a protocol-relative or absolute URL, leading to an open redirect.

### Impact

An attacker could craft a malicious URL that, when processed by `webob` and used in a `Location` header for a redirect, would redirect users to an arbitrary external site controlled by the attacker. This could be used for phishing attacks, tricking users into revealing credentials or downloading malware.

### Key diff

```
--- a/src/webob/request.py
+++ b/src/webob/request.py
-        return urlparse.urljoin(url, other_url)
+        return urljoin(url, other_url)
--- a/src/webob/exc.py
+++ b/src/webob/exc.py
-        self.location = urlparse.urljoin(req.path_url, self.location)
+        self.location = self._make_location_absolute(environ, self.location)
```

### Fix summary

The patch replaces the use of `urllib.parse.urljoin` with a custom `urljoin` implementation within `webob.util`. This new implementation strictly adheres to RFC 3986 for URI resolution, without performing any whitespace removal or stripping of C0 control characters. This ensures that URLs are processed exactly as provided, preventing malicious whitespace from being interpreted as a valid scheme or authority.

## GHSA-vxj7-4xrp-5vr4 · aiosmtplib

2026-08-27 · Python · **MODERATE** 5.9 · Pattern: `UNCLASSIFIED`

### Root cause

The vulnerability existed because the aiosmtplib client did not clear its internal read buffer before initiating a STARTTLS handshake. This allowed a Man-in-the-Middle (MITM) attacker to inject plaintext commands into the buffer, which would then be processed as part of the encrypted session after the TLS handshake completed.

### Impact

An attacker could inject arbitrary SMTP commands, potentially leading to command execution, data leakage, or other unauthorized actions within the SMTP session, despite the use of STARTTLS.

### Key diff

```
--- a/src/aiosmtplib/protocol.py
+++ b/src/aiosmtplib/protocol.py
@@ -379,6 +379,13 @@ async def start_tls(
             if self.transport is None or self.transport.is_closing():
                 raise SMTPServerDisconnected("Connection lost")
 
+            # STARTTLS injection defense (RFC 3207 section 4.2):
+            # Any bytes still buffered here are plaintext a MITM may have
+            # injected; discard them so they cannot be misread as part of the
+            # encrypted session once the handshake completes.
+            del self._buffer[:]
+
             try:
                 tls_transport = await self._loop.start_tls(
                     cast(asyncio.WriteTransport, self.transport),
```

### Fix summary

The patch addresses the vulnerability by clearing the internal read buffer (`self._buffer[:]`) immediately before the `_loop.start_tls` call. This ensures that any plaintext data injected by a MITM attacker before the TLS handshake is discarded and not processed as part of the secure session.
