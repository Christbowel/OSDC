## GHSA-gvrw-qqp5-jgc5 · silverstripe/framework

2026-08-27 · PHP · **MODERATE** 5.4 · Pattern: `UNSANITIZED_INPUT→XSS`

### Root cause

The application allowed embedding of external media content via shortcodes. When the embedded HTML was simple (containing two or fewer HTML tags), it was returned directly without proper sanitization. This allowed an attacker to inject malicious attributes, such as 'onload' or 'src' with dangerous schemes (e.g., 'javascript:'), into an iframe tag, leading to Cross-Site Scripting.

### Impact

An attacker could inject arbitrary client-side scripts into the web page, leading to session hijacking, defacement, redirection to malicious sites, or other client-side attacks.

### Fix summary

The patch introduces a new function, `removeDangerousAttributes`, which is called when an iframe is not sandboxed. This function strips all attributes from the iframe tag except for a predefined list of safe attributes and also validates the 'src' attribute to prevent dangerous schemes like 'javascript:' or 'data:' from being used.

## GHSA-r5pm-vrc5-3m73 · cakephp/queue

2026-08-27 · PHP · **LOW** 3.7 · Pattern: `WEAK_CRYPTO→HASH`

### Root cause

The original `getUniqueId` method used `sort($data)` to normalize the input array before hashing. However, `sort()` only sorts the values of the top-level array and does not handle nested arrays or sort by keys, leading to different hash outputs for semantically identical data if array keys or nested array order differed.

### Impact

This vulnerability could lead to hash collisions for queue jobs, meaning two distinct jobs with different data structures but semantically equivalent content might be treated as the same unique job. This could result in jobs not being processed when they should be, or incorrect job deduplication.

### Fix summary

The patch introduces a new recursive sorting function, `sortUniqueValues`, which sorts both the keys and values of an array, including nested arrays. This ensures that the input data is consistently ordered before hashing, preventing collisions for semantically equivalent job data.

## GHSA-q7m3-rhxg-7vxr · n8n-nodes-sqlite3

2026-08-27 · JavaScript · **MODERATE** 0.0 · Pattern: `PATH_TRAVERSAL→FILE_WRITE`

### Root cause

The application allowed user-controlled input for the 'db_path' parameter without proper sanitization or validation. This meant that an attacker could supply a path containing directory traversal sequences (e.g., '..') to access or create database files outside the intended directory.

### Impact

An attacker could read, write, or overwrite arbitrary SQLite database files on the server's file system, potentially leading to data leakage, data corruption, or denial of service if critical files are overwritten.

### Fix summary

The patch adds the 'noDataExpression: true' property to the 'db_path' parameter. This prevents the parameter from being dynamically set by user-controlled data expressions, effectively removing the path traversal vector.
