## GHSA-2xhg-73j7-rrgx · @contentful/mcp-tools

2026-08-19 · JavaScript · **HIGH** 7.7 · Pattern: `SSRF→INTERNAL_ACCESS`

### Root cause

The Contentful MCP Server's export_space/import_space tools were vulnerable because they allowed LLM-controlled 'host' and 'proxy' arguments to be passed directly to the Contentful Management API (CMA) client. This meant an attacker could manipulate these arguments to redirect the server's Personal Access Token (PAT) to an arbitrary, attacker-controlled endpoint.

### Impact

An attacker could exfiltrate the server's Contentful Personal Access Token (PAT) by redirecting API requests to a malicious server, potentially gaining unauthorized access to Contentful spaces and data.

### Fix summary

The patch introduces new environment variables and configuration options for Contentful Delivery API (CDA) token and host. Specifically, it adds `CONTENTFUL_DELIVERY_TOKEN` and `CONTENTFUL_DELIVERY_HOST` to the server's environment schema and `deliveryToken` and `hostDelivery` to the MCP tools configuration, ensuring that these sensitive parameters are explicitly defined and controlled, rather than being implicitly derived or attacker-controlled.

## GHSA-rgr9-r7mj-mf6x · @tinacms/cli

2026-08-19 · JavaScript · **MODERATE** 6.5 · Pattern: `CSRF→STATE_CHANGE`

### Root cause

The Tina CMS dev server used the `cors` npm package, but only for setting `Access-Control-Allow-Origin` headers. It did not explicitly reject cross-origin requests for state-changing endpoints like `/media/upload/*`. This meant that 'simple' requests, such as multipart form data uploads, could bypass the CORS preflight and be initiated from an attacker-controlled origin.

### Impact

An attacker could craft a malicious web page that, when visited by a user logged into the Tina dev server, could force the user's browser to send `POST /media/upload/*` requests. This would allow the attacker to upload arbitrary files to the Tina dev server's media root, potentially leading to defacement, further compromise, or denial of service.

### Root cause

The vulnerability existed because the `saveDocument` method in the `ModelBridge` class did not properly check the user's script rights before saving a document. ### Impact

```
-            document.setAuthorReference(xcontext.getUserReference());
```

### Fix summary

## GHSA-vwg3-w8w3-pc79 · getgrav/grav

2026-08-19 · PHP · **HIGH** 0.0 · Pattern: `INSECURE_DEFAULT→CONFIG`

### Root cause

The vulnerability stemmed from the Apache .htaccess rewrite rules not being case-insensitive. On filesystems that are case-insensitive (like Windows or macOS), an attacker could bypass security restrictions by requesting a file with a different casing (e.g., 'User/accounts/config.yaml' instead of 'user/accounts/config.yaml'), thereby gaining unauthorized access to sensitive files.

### Impact

An attacker could gain unauthorized access to sensitive configuration files, user accounts, logs, or other protected system files, potentially leading to information disclosure, privilege escalation, or further system compromise.


### Fix summary

The patch addresses the vulnerability by adding the '[NC]' flag (No Case-insensitivity) to all relevant RewriteRule directives in the .htaccess file. This ensures that the security rules are applied regardless of the casing used in the requested URL, effectively blocking bypass attempts on case-insensitive filesystems.
