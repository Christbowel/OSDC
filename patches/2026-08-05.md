## GHSA-hxvh-4h3w-prp9 · nuxt

2026-08-05 · JavaScript · **HIGH** 8.2 · Pattern: `MISSING_AUTH→ENDPOINT`

### Root cause

The Nuxt framework's route rules, which are used for security-sensitive configurations like authentication middleware, were being matched case-sensitively by the underlying `rou3` router. However, the `vue-router` (which handles client-side routing) often operates case-insensitively by default. This mismatch meant that if a route rule was defined with a mixed-case path (e.g., `/Admin`), but a user accessed the path with a different casing (e.g., `/admin`), the route rule would silently fail to apply, bypassing intended security controls.

### Impact

An attacker could bypass `appMiddleware` authentication gates or other security-sensitive route rules by requesting a mixed-case version of a path, gaining unauthorized access to protected resources or functionality.

An attacker could achieve server-side command execution on the SFTP server by crafting a malicious filename. This could lead to full compromise of the server where rclone is running.

## GHSA-cf44-9pgv-m4xc · github.com/rclone/rclone

2026-08-05 · Go · **HIGH** 7.5 · Pattern: `PATH_TRAVERSAL→FILE_WRITE`

### Root cause

The rclone tool, when configured with `--links` to translate symlinks, did not properly validate the target of symlinks received from an untrusted remote. It would create directories and open files directly using the `localPath` derived from the remote, without anchoring these operations to the intended root directory. This allowed a malicious remote to plant a symlink that, when followed by subsequent operations (like creating a directory or writing a file), could escape the intended destination directory and write to arbitrary locations on the local filesystem.

### Impact

An attacker controlling a remote rclone server could craft a malicious symlink that, when synced by a client using the `--links` option, could lead to arbitrary file writes on the client's system outside of the designated sync directory. This could result in overwriting critical system files or injecting malicious content.

## GHSA-pfmc-3mgc-p6fp · electron

2026-08-05 · JavaScript · **LOW** 3.9 · Pattern: `INTEGER_OVERFLOW→BOUNDARY`

### Root cause

The Electron off-screen rendering component trusted geometry information (e.g., content_rect, pixel_size) received from the potentially malicious GPU process over Mojo. This information was used to size bitmaps and canvases backed by shared memory without proper validation against the actual shared memory mapping size, leading to potential out-of-bounds reads.

### Impact

An attacker controlling the GPU process could craft malicious geometry data to cause the browser process to read past the bounds of a shared memory mapping. This could lead to information disclosure (reading sensitive data from adjacent memory) or a crash (denial of service).

### Root cause

### Impact

An attacker could potentially access or manipulate files outside the intended restic repository root, leading to unauthorized data access, modification, or deletion on the server's filesystem.


### Fix summary

## GHSA-qq9q-x9w4-chhj · Traefik

### Root cause

The vulnerability existed because Traefik's Gateway API HTTPRoute processing incorrectly used the namespace of the `BackendRef` (which could be user-controlled) instead of the `HTTPRoute` itself when loading middlewares.
