## GHSA-7w38-ggh5-v542 · @enspirit/elo

2026-11-03 · JavaScript · **CRITICAL** 9.8 · Pattern: `UNSANITIZED_INPUT→TEMPLATE`

### Root cause

The application was generating Ruby code by embedding user-controlled strings (string literals and constraint labels) directly into double-quoted Ruby string literals without properly escaping the '#' character. This allowed an attacker to inject `#{...}` interpolation sequences, which Ruby would then evaluate as code.

### Impact

An attacker could inject arbitrary Ruby code, leading to remote code execution on the server where the generated Ruby code is executed.

### Key diff

```
-      const escaped = ir.value.replace(/\\/g, '\\\\').replace(/"/g, '\"').replace(/\n/g, '\\n').replace(/\t/g, '\\t').replace(/\r/g, '\\r');
-      return `"${escaped}"`;
+      return `"${escapeRubyDQ(ir.value)}"`;
...
-        return `return p_fail(p, "${errorMsg}") unless (${conditionCode});`;
+        return `return p_fail(p, "${escapeRubyDQ(errorMsg)}") unless (${conditionCode});`;
```

### Fix summary

A new `escapeRubyDQ` function was introduced to properly escape special characters, including '#', backslashes, double quotes, and control characters, for embedding within Ruby double-quoted string literals. This function is now used for all user-controlled string literals and constraint labels to prevent interpolation-based code injection.

## GHSA-j97h-3f8r-mrjr · org.keycloak:keycloak-services

2026-11-03 · Java · **HIGH** 8.1 · Pattern: `TYPE_CONFUSION→BYPASS`

### Root cause

The vulnerability stemmed from an algorithm confusion issue in JWT validation. Keycloak's JWT validation logic did not adequately restrict the use of symmetric algorithms (like HMAC) when an asymmetric algorithm (like RSA) was expected. An attacker could craft a JWT signed with a symmetric key, using the public key of the legitimate client as the symmetric key, and the validator would incorrectly attempt to verify it with the provided 'public key' as a shared secret, leading to a successful authentication bypass.

### Impact

An attacker could bypass authentication mechanisms that rely on JWTs, potentially gaining unauthorized access to client accounts or resources within Keycloak.

2026-11-03 · C# · **HIGH** 8.1 · Pattern: `BUFFER_OVERFLOW→HEAP`

## GHSA-h26j-4vp7-x9w2 · Metalama.Framework

2026-11-03 · C# · **HIGH** 7.3 · Pattern: `DESERIALIZATION→RCE`

### Root cause

The application used Newtonsoft.Json with `TypeNameHandling.All` for inter-process communication over a named pipe. This setting embeds CLR type names in the serialized data, allowing the deserializer to instantiate any type specified in the incoming data. Without proper restrictions, this enabled an attacker to instantiate arbitrary types from allow-listed assemblies, including core system libraries, leading to a gadget-chain RCE.

### Impact

An attacker with local access to the named pipe could achieve arbitrary code execution by sending specially crafted serialized objects that leverage existing 'gadget' classes within the application's dependencies.
