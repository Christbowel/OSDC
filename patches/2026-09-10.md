## GHSA-jmc6-2wr8-h3wj · open-webui

2026-09-10 · Python · **HIGH** 8.7 · Pattern: `INSECURE_DEFAULT→CONFIG`

### Root cause

The application hardcoded 'allow-same-origin' in the sandbox attribute of an iframe used for port previews. This allowed content loaded within the iframe, even from a different origin (via a proxy), to bypass the same-origin policy and interact with the parent document, leading to a same-origin XSS vulnerability.

### Impact

An attacker could inject malicious scripts into the iframe, which would then be able to access and manipulate the parent document's DOM, steal user credentials (e.g., session tokens), or perform actions on behalf of the user, potentially leading to account takeover.

### Key diff

```
-				sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-modals allow-downloads"
+				sandbox="allow-scripts{($settings?.terminalPreviewAllowSameOrigin ?? true)
+					? ' allow-same-origin'
+					: ''} allow-forms allow-popups allow-modals allow-downloads"
```

### Fix summary

The patch introduces a new user setting, `terminalPreviewAllowSameOrigin`, which controls whether the 'allow-same-origin' directive is included in the iframe's sandbox attribute. By default, this setting is now configurable, allowing users to disable the 'allow-same-origin' behavior and enhance security.

## GHSA-4v28-j6q3-5m4r · open-webui

2026-09-10 · Python · **HIGH** 7.7 · Pattern: `SSRF→INTERNAL_ACCESS`

### Root cause

The Playwright web loader component, when processing user-supplied URLs, relied on the browser to resolve hostnames. This allowed an attacker to use DNS rebinding techniques to bypass initial URL validation checks, which only verified the IP address at the time of connection. After the initial check, a malicious DNS server could resolve the hostname to an internal IP address, leading to server-side request forgery.

### Impact

An attacker could bypass URL validation and make requests to internal services or resources within the network where the Open WebUI application is running, potentially leading to information disclosure or further compromise.

### Key diff

```

-            validate_url(req.url)
-            resp = route.fetch(max_redirects=0)
+            def fetch(url):
+                validate_url(url)
+                return session.request(
+                    req.method,
+                    url,
```

### Fix summary

The patch modifies the `SafePlaywrightURLLoader` to intercept navigation requests and perform the hostname resolution and URL validation directly within the application's `_SSRFSafeResolver` before allowing the request to proceed. This ensures that all hops, including redirects, are validated against internal IP ranges, preventing DNS rebinding attacks.

## GHSA-2724-6cpj-gf3v · open-webui

2026-09-10 · Python · **HIGH** 7.1 · Pattern: `MISSING_AUTHZ→RESOURCE`

### Root cause

The application allowed any authenticated user to delete a knowledge base. When an external knowledge base was deleted, the associated external connection was also deleted if it was no longer referenced by other knowledge bases. The critical flaw was that the check for deleting the external connection did not verify if the user initiating the deletion had administrative privileges, even though these connections are admin-owned.

### Impact

A non-admin user could delete external knowledge connections that were created and owned by an administrator. This could lead to denial of service for other users or services relying on these connections, as the external data sources would become inaccessible.

### Fix summary

The patch adds an authorization check to ensure that only users with an 'admin' role can delete external knowledge connections. Additionally, it verifies that the connection is no longer mapped to any other knowledge bases before deletion, preventing accidental removal of shared resources.
