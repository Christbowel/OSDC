## GHSA-mmj4-63m4-r6h5 · codeigniter4/framework

2026-08-07 · PHP · **CRITICAL** 9.8 · Pattern: `UNCLASSIFIED`

### Root cause

The vulnerability existed because the file validation rules `is_image` and `mime_in` in CodeIgniter only checked the detected MIME type or the file's actual content type, but did not adequately validate the client-provided file extension against the actual content or expected image types. This allowed an attacker to upload malicious files with a misleading extension (e.g., a PHP script disguised as an image) if the server relied solely on these rules.

### Impact

An attacker could bypass file upload restrictions, potentially uploading malicious scripts (e.g., PHP web shells) to the server. If these files were then accessible and executable, it could lead to Remote Code Execution (RCE) on the server, allowing the attacker to take full control.

### Fix summary

The patch introduces two new private methods: `hasInvalidImageClientExtension` and `hasMismatchedClientExtension`. These methods are called within the `is_image` and `mime_in` validation rules, respectively. They perform additional checks to ensure that the client-provided file extension is consistent with the file's detected content type, specifically rejecting non-image extensions for image files and mismatched extensions for MIME type checks.

## GHSA-fwg2-594c-jp42 · pypdf

2026-08-07 · Python · **MODERATE** 0.0 · Pattern: `DOS→RESOURCE_EXHAUSTION`

### Root cause

The pypdf library did not properly validate the size of CID font width ranges or the total number of character width entries when parsing PDF files. Maliciously crafted PDF files could specify extremely large ranges or a huge number of individual width entries, leading to excessive memory allocation and long processing times.

### Impact

An attacker could craft a PDF file that, when processed by pypdf, would consume an inordinate amount of memory or CPU time, potentially leading to a denial of service for applications using the library.

## GHSA-wg23-69c2-gjc8 · craftcms/cms

2026-08-07 · PHP · **CRITICAL** 0.0 · Pattern: `MISSING_VERIFICATION→SIGNATURE`

### Root cause

The vulnerability existed because the WebAuthn assertion used for passkey login was not properly bound to a single-use session, allowing an attacker to intercept and replay a valid assertion to authenticate as the legitimate user. The system did not ensure that the `requestOptions` were consumed after a single successful use.

### Impact

An attacker could intercept a legitimate user's WebAuthn assertion during a passkey login and replay it to gain unauthorized access to the user's account, effectively bypassing the passkey authentication mechanism.
