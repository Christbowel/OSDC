## GHSA-49mq-fc6q-3h46 · @ooples/token-optimizer-mcp

2026-08-14 · JavaScript · **HIGH** 8.4 · Pattern: `UNSANITIZED_INPUT→COMMAND`

### Root cause

The application was vulnerable to OS command injection because it used `exec` with unsanitized user input when managing cron jobs and Windows scheduled tasks. Additionally, it was vulnerable to path traversal due to concatenating user-supplied `sessionId` into file paths without proper validation, allowing access to arbitrary files.

### Impact

An attacker could execute arbitrary operating system commands on the server, leading to full system compromise. They could also read arbitrary files on the server's filesystem, potentially exfiltrating sensitive data.

### Key diff

```
--- a/src/tools/system-operations/smart-cron.ts
+++ b/src/tools/system-operations/smart-cron.ts
-      const { stdout } = await execAsync('crontab -l');
+      const { stdout } = await execFileSafe('crontab', ['-l']);
--- a/src/server/web-server.ts
+++ b/src/server/web-server.ts
-    const jsonlFilePath = path.join(
-      hooksDataPath,
-      `session-log-${sessionId}.jsonl`
-    );
+    if (!isValidSessionId(sessionId)) {
+      return res.status(400).json({
+        success: false,
+        error: 'Invalid sessionId',
+      });
+    }
+
+    const jsonlFilePath = resolveSessionLogPath(sessionId);
```

### Fix summary

The patch replaces `exec` with `execFileSafe` and `spawnSafe` for command execution, ensuring that arguments are passed as an array and preventing shell interpretation. It also introduces strict validation for `sessionId` using a regular expression and a `resolveSessionLogPath` function to ensure that resolved paths remain within the intended directory, preventing path traversal.

## GHSA-2j9v-p4xj-cjw2 · github.com/lima-vm/lima/v2

2026-08-14 · Go · **HIGH** 8.2 · Pattern: `PRIVILEGE_ESCALATION→ROLE`

### Root cause

The lima-guestagent UNIX socket was created with world-writable permissions (0o777), allowing any user within the QEMU VM to connect to it. Since the guest agent runs as root, an arbitrary user could interact with the agent via this socket and potentially execute privileged operations.

### Impact

An attacker with an unprivileged user account inside the QEMU VM could connect to the guest agent socket and leverage its root privileges to gain root access within the VM.

### Key diff

+		// that user so 0600 restricts access to the main user rather than root.

The socket's permissions are changed from 0o777 (world-writable) to 0o600, restricting access to only the specified owner and root. The systemd unit generation is updated to pass the main user's UID to the guest agent.

## GHSA-8rw6-p7m8-63jp · surrealdb

2026-08-14 · RUST · **MODERATE** 6.5 · Pattern: `INFO_DISCLOSURE→ERROR_MESSAGE`

### Root cause

The vulnerability stemmed from an incorrect iteration order when removing denied array elements. When `Value::cut` removed an element from a `Vec`, it shifted subsequent elements, invalidating the indices for a forward iteration. This caused the permission filtering logic to skip certain elements, effectively leaking them.

### Impact

An attacker with record-level access could bypass field-level `DENY` or `CONDITIONAL` permissions on array elements, allowing them to read data that should have been restricted.

### Key diff

```
- for path in original.each(&idiom.0) {
+ for path in original.each(&idiom.0).into_iter().rev() {
  	value.cut(&path.0);
  }
```

### Fix summary

The patch reverses the iteration order for removing array elements. By iterating from the highest index to the lowest, `Value::cut` operations no longer invalidate the indices of elements yet to be processed, ensuring all denied elements are correctly removed.
